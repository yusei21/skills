# 高级使用指南

[English](./GUIDE.md) | [Português](./GUIA.md) | **简体中文**

本指南假设仓库已经安装完成（安装说明见 [`README.zh-CN.md`](../README.zh-CN.md)）。这里重点介绍如何高效使用仓库中的各类资源。

## 1. 何时使用不同类型的资源

| 资源 | 用途 | 何时触发 |
|---|---|---|
| **Agents** (`agents/`) | 委派范围明确的任务，例如代码审查或构建错误处理 | 当任务定义清楚且相对独立时，让智能体单独执行，避免污染主上下文 |
| **Skills** (`skills/`) | 可复用工作流和领域知识 | 日常使用的主要入口，可直接调用，也可由工具根据任务自动选择 |
| **Rules** (`rules/`) | 始终生效的规范，例如代码风格、测试和安全要求 | 用于统一行为，而无需在每个任务中重复说明 |
| **Hooks** (`hooks/`) | 由事件触发的自动化，例如阻止提交泄露的 secret | 配置一次后自动执行 |
| **Commands** (`commands/`) | 面向特定 skill 或流程的 `/slash` 快捷入口 | 希望快速触发流程而不需要完整描述任务时 |

## 2. 常见工作流

### 开始新功能

```text
/plan "功能描述"          → 规划智能体生成蓝图
TDD skill                 → 先写测试，再写实现
/code-review              → 进行质量与安全审查
```

### 修复 bug

```text
TDD skill     → 编写能够复现 bug 的失败测试
                 → 实现修复并确认测试通过
/code-review  → 检查是否引入回归
```

### 准备上线

```text
/security-scan      → 安全检查清单
E2E testing skill   → 测试关键用户流程
/test-coverage      → 检查测试覆盖率
```

上面的命令和 skill 名称应根据仓库中实际存在的内容调整。可使用 `/plugin list skills@skills` 查看实际列表。

## 3. 组合 agents 与 skills

智能体可以在自己的执行流程中调用 skill。例如，代码审查智能体可以先使用安全模式相关的 skill，再给出最终结论。创建新的智能体时，应优先引用已有 skill，而不是复制知识，这能降低维护成本并减少内容漂移。

## 4. 通用规则与语言特定规则

应始终加载 `rules/common/` 中的通用规则，同时只加入当前项目真正使用的语言规则。这样可以避免：

- 无关内容占用上下文和 token；
- 不同语言生态之间产生不必要的约定冲突。

## 5. Token 与成本优化

- 大多数任务使用默认的均衡模型即可，仅在需要更深推理时切换到更昂贵的模型；
- 不相关任务之间使用 `/clear` 清理上下文；
- 在研究结束、实现开始前，或完成一个明确里程碑后使用 `/compact`；不要在实现中途压缩关键状态；
- 不要同时启用过多 MCP 服务器，每个暴露的工具都会增加上下文和攻击面；
- 使用 `project-orchestrator` 只加载当前任务真正需要的技能和专家角色。

## 6. 从其他仓库加入内容

引入其他仓库中的代码、skill 或配置之前：

1. 先检查来源许可证：
   - **MIT / Apache-2.0 / BSD：** 通常允许在保留要求的前提下复用和改编；
   - **GPL / AGPL：** 必须仔细评估其传播和分发要求；
   - **未声明许可证：** 未获得明确许可前不要复制；
2. 审查 skill 本身以及随附的脚本、依赖和资源，避免 prompt injection、危险命令、凭据读取或数据外传；
3. 优先基于公开模式自行实现，而不是直接复制不需要的内容；
4. 将内容放入对应的规范目录（`agents/`、`skills/`、`rules/` 等）；
5. 如果实际复制或改编了第三方受版权保护的内容，请更新 `NOTICE.md`、`NOTICE.en.md` 和 `NOTICE.zh-CN.md`，记录来源、版权、许可证以及保留或修改的内容。

## 7. 自定义已有内容

继承和收集的内容只是起点：

1. 从真正符合当前工作流的内容开始；
2. 根据实际技术栈调整 rules 和 skills；
3. 删除长期不用的内容，减少上下文与维护成本；
4. 将反复出现并经过验证的工作方式沉淀为新的 skill；
5. 定期审查目录，合并重复能力，并淘汰已经过时的说明。
